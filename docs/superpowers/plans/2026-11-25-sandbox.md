# Sandbox (Milestone 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run a reporter's PoC at the resolved ref inside a gVisor sandbox, recognise reproduction by deterministic signals tied to the claimed code, run a HEAD control, and fold the result into the verdict.

**Architecture:** A new `internal/sandbox` package exposes one `Runner`. Pure parts (PoC validation and placement, OCI config generation, output-signal parsing) are unit tested on any OS. A thin `runsc` driver shells out to gVisor behind a `driver` interface so phase orchestration is tested against a fake driver. The pipeline gets `WithSandbox`; `verdict.Compose` gains the repro outcomes.

**Tech Stack:** Go standard library only; `runsc` (gVisor) and a Go-toolchain rootfs as runtime prerequisites. No new Go modules.

**Spec:** `docs/superpowers/specs/2026-11-25-sandbox-design.md` (read it first; it is the requirement). Also `CLAUDE.md` "Sandbox spec" and `docs/threat-model.md`.

## Global Constraints

- Commit straight to `main` with `git commit -s`; `git push origin main` after every commit. No branches, worktrees or PRs. Conventional commits; messages for changes to verdict/eval carry the eval scoreboard.
- Standard library only. Third-party module stays `modernc.org/sqlite`.
- Never wrongly reject a real report: every sandbox failure (runtime missing, build error, timeout, odd output) is `INCONCLUSIVE`; the sandbox never produces `GROUNDING_FAILED`.
- Everything from a report is hostile: PoC names and content, `go.mod`, program output. Output shown to humans goes through `report.Printable`.
- No network in build and run phases; network only in the fetch phase, restricted by `GOPROXY=<configured proxy>` (no `direct`), `GOTOOLCHAIN=local`, `GOWORK=off`. The PoC is not in the container during fetch.
- Never mount or pass: Docker socket, data dir, signing key, GitHub token, host environment. Environment is built from scratch.
- Exact `runsc` flags come from the gVisor docs for the installed version, never from memory. Verified so far: `--network=none`, `--platform=systrap`, `--ignore-cgroups` (release-20261102.0, linux/arm64).
- Sandbox integration tests use the `sandbox` build tag; everything else runs in plain `go test ./...` on any OS.
- Config defaults: `runtime` `runsc`, `goproxy` `https://proxy.golang.org`, `fetch_timeout_seconds` 300, `build_timeout_seconds` 300, `run_timeout_seconds` 120, `memory_mb` 2048, `cpus` 2, `pids` 512, `output_limit_kb` 1024.
- PoC limits: at most 64 files, each at most 256 KiB; names are plain file names (sole exception: `testdata/fuzz/<FuzzName>/<seed>`).
- Model use in this repo: opus and sonnet for tasks; the final whole-branch review may use fable (owner allowed it for this session).
- Run `gofmt -l cmd internal && go vet ./... && go test -race ./...` before every commit; the commit hook runs the quality gate, fix failures, never skip.

## Review Focus

- A report whose PoC file name is `../x`, absolute, a symlink, or has an odd Unicode name must be refused before anything is copied (Task 3).
- A PoC that only crashes, calls `os.Exit(1)`, or panics outside claimed code must not reproduce (Task 5).
- A report claiming a stdlib or dependency function (grounding `unknown`) plus any panic must not reproduce (Task 5).
- A hostile `go.mod` (`replace` to a host path, `toolchain` line, `go` newer than the rootfs) must end `INCONCLUSIVE`, with nothing from the host read (Tasks 3, 7).
- Orphaned containers and scratch directories after a host crash or Ctrl-C must be cleaned on next start and on cancellation (Task 6).
